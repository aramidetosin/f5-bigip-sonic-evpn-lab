# F5 BIG-IP on a SONiC EVPN fabric: a containerlab lab

A lab for learning **F5 BIG-IP Local Traffic Manager** inside a realistic data-centre network: a SONiC spine-leaf EVPN/VXLAN fabric,
a firewall between two VRFs, and two blank BIG-IPs, built by one script.

## What's in it (20 nodes)

| Nodes | What |
|---|---|
| spine1-2, three leaf pairs (border, service, server) | Dell Enterprise SONiC 4.6: eBGP unnumbered underlay, BGP EVPN / VXLAN, symmetric IRB with anycast gateways, EVPN multihoming (ESI-LAG) |
| fw-pa | Palo Alto PA-VM 12.1.2: the only path between the two VRFs (Vrf-Outside: users, Vrf-App: servers and BIG-IPs), eBGP to both sides |
| lb-f5a, lb-f5b | F5 BIG-IP VE 17.5.1: **left blank and unlicensed**, management reachable only; you configure them |
| server1-3 | nginx "whoami" pages (http / https with a lab CA), one colour per server |
| log-server, sorry-server | rsyslog + SNMP traps; a maintenance page |
| lan-switch, pc1-3 | the users' LAN; each PC runs Firefox in a web desktop |

Two designs share the same cables:
- **Basic:** course-style two-arm. The BIG-IP ports carry the basic VLANs untagged.
- **Advanced:** BGP from the BIG-IPs to the service leaves, with route health injection. The same ports carry the advanced transits
  tagged.

The switches and firewall are configured for both; the BIG-IP configuration decides which one is live.

## Prerequisites

- Linux with Docker and [containerlab](https://containerlab.dev) (tested with 0.82), KVM, about 100 GiB of free RAM.
- Three appliance images that you build yourself with [vrnetlab](https://github.com/hellt/vrnetlab) from your own licensed / evaluation
  images:
  - `vrnetlab/dell_sonic:4.6.0`
  - `vrnetlab/paloalto_pa-vm:12.1.2`
  - `vrnetlab/f5_bigip-ve:17.5.1.11-0.0.12`
- Python 3, `sshpass`, `openssl`, `nft`, `curl`.
- The small Linux images (`images/`) are built by `up.sh` itself.

## Use it

Every name, address, VLAN and AS number lives in `gen.py`, which generates the topology, the switch configurations and the firewall
configuration. Adjust `LAN_IF` (the host interface the management network is masqueraded out of) and `MGMT` in it first.

```bash
python3 gen.py      # regenerate the topology and configs after any change
./up.sh --check     # preflight only
./up.sh             # build everything: about 11 minutes, ends with 36 automatic checks
./validate.sh       # run the checks again at any time
./down.sh           # save both BIG-IP configs (UCS), refuse while a BIG-IP holds a licence, destroy
```

`secrets-init.sh` creates the lab's passwords, SSH keys and lab CA in `/root/f5-clos-dc-secrets` (root-only) on the first run. They
are never written into this folder. Revoke any BIG-IP licence before `./down.sh`: an evaluation key bound to a deleted VM is lost.
`./f5-save.sh` / `./f5-restore.sh` save and restore your BIG-IP work as UCS.

## Layout

| Path | What |
|---|---|
| `gen.py` | the single source of every value |
| `f5-clos-dc.clab.yml`, `configs/`, `bootstrap/`, `mgmt-hosts.txt`, `images.txt` | generated by `gen.py` (`up.sh` runs it first; not committed) |
| `up.sh`, `down.sh`, `validate.sh` | build, tear down, check |
| `sonic-apply.sh`, `pa-load.sh`, `ssh-keys.sh`, `mgmt-access.sh`, `lib.sh` | the stages `up.sh` runs |
| `shared/`, `images/` | the Linux nodes' startup scripts and Dockerfiles; `images/pa-launch/` is the PA-VM image's vrnetlab launcher with one fix, mounted for fw-pa |
